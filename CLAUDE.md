# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
npm install

# First-time setup: generate pg-container.config.ts values, then edit .env
npm run create-pg-container-config

# Start / stop the dev Postgres container (requires Docker)
npm run pg-dev:start
npm run pg-dev:stop

# Start / stop the test Postgres container
npm run pg-test:start
npm run pg-test:stop

# Run the server (port 4000)
npm start

# Run database migrations (wraps dbmate; pass dbmate subcommands as args, e.g. "up", "down", "new <name>")
npm run migrations up

# Run database tests (pgTAP-based SQL tests; requires test container running)
npm run test:db

# Generate TypeScript types from the live database schema → src/model/db/generated-types.ts
npm run gen-types:db

# Generate TypeScript types from GraphQL schema → src/model/graphql/generated-types.ts
npm run gen-types:gql

# Format code
npm run format

# Generate GraphQL schema diagram (requires server running)
npm run gen-diagram:gql
```

## Architecture

### Overview

This is an Express + Apollo Server 5 GraphQL API backed by PostgreSQL. The server runs at `http://localhost:4000`. The `AppContext` carries the client's IANA timezone (from the `Time-Zone` request header), which is threaded through resolvers to calculate timezone-aware reward expiry dates.

### Layer structure

```
src/
  index.ts              — Express + Apollo wiring, charset validation
  graphql/
    schema/             — GraphQL SDL files (auto-merged at startup via @graphql-tools)
    resolvers/
      functions/        — Resolver implementations (partner, location, reward, language)
      sql/              — Kysely query builders, one subdirectory per entity
        common/         — Reusable filter expression builders (string, bigint, datetime…)
      voucher/          — Voucher retrieval mutation
  db/
    migrations/         — dbmate SQL migration files
    __tests__/          — pgTAP SQL test files (setup.sql + test-*.sql)
  model/
    db/                 — Kysely DB interface (generated-types.ts) + Point type
    graphql/            — Apollo resolver types (generated-types.ts) + AppContext
  scripts/              — CLI utilities (pg container, migrations, type generation, tests)
  util/                 — parseTimeZoneHeader, setCustomTypeParsers (geography→Point, bigint)
```

### Type generation

There are two generated type files that must be kept in sync with their sources:

- **`src/model/db/generated-types.ts`** — generated by `introspeql-kysely` from the live database schema. Re-run `npm run gen-types:db` after any migration.
- **`src/model/graphql/generated-types.ts`** — generated by `graphql-codegen` (using the `gqlarr` plugin) from all `.graphql` SDL files. Re-run `npm run gen-types:gql` after any schema change.

Neither file should be edited by hand.

### Database views

The API queries PostgreSQL views rather than base tables. The views enforce data integrity invariants (e.g., a partner must have translations in all supported languages to appear). Key views used in queries:

- `public.v_active_partner` — partners that are active and fully translated
- `public.v_active_partner_location` — locations whose partner is in `v_active_partner`
- `public.v_valid_reward` — rewards whose partner is active and all categories are fully translated
- `public.get_available_rewards_in_timezone(timezone)` — table-valued function returning rewards available in a given timezone (used for all reward queries)

### SQL query builders (`src/graphql/resolvers/sql/`)

Each entity (`partner`, `location`, `reward`, `language`) has:
- `create-select-statement.ts` — builds the `SELECT` using Kysely, driven by the GraphQL field selection (`RewardFields`, etc.) so only requested columns are fetched
- `create-filter-expression.ts` — recursively maps a GraphQL filter input (`_and`, `_or`, `_not`, leaf filters) to a Kysely `Expression<SqlBool>`
- `create-count-statement.ts` / `apply-order-by-clause.ts` — count queries and ORDER BY application

The `common/` folder contains reusable `create-*-filter-expression` helpers for each GraphQL scalar filter type.

### Resolver pattern

Each resolver (e.g., `src/graphql/resolvers/functions/partner/partners.ts`) is typed against `QueryPartnersResolver<AppContext>`. Currently most resolvers throw `'Not implemented'`; the SQL layer is further along than the resolver layer.

### Database tests

Tests live in `src/db/__tests__/` as pgTAP SQL files. `setup.sql` creates test fixtures; `test-*.sql` files define test functions. `npm run test:db` drops and recreates the test database, applies all migrations, loads the test files, and runs `pg_prove`. Requires `pg_prove` (from the `pgtap` package) to be installed locally.

### Docker / Postgres containers

`src/scripts/pg.ts` manages Docker containers using the image built from `src/docker/Dockerfile`. The `pg-container.config.ts` file holds container names, ports, volumes, and dummy passwords (not secrets — the Postgres container is local only). Dev and test containers run on separate ports to allow both simultaneously.
